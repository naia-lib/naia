# naia — agent entrypoint

Spec files: `test/specs/contracts/` (start at `test/specs/contracts/00_common.spec.md`); design docs in `book/` and `docs/`.

Application boundary (`00_common.spec.md` §7, Connor 2026-10-27): naia owns connection lifecycle, transport, typed-message delivery and entity replication. Application state and policy belong to the application protocol and its consumer — no game names, fixed player counts or gameplay deadlines in public naia APIs. Check each new public type, fixed limit and state transition against that rule before landing on `dev`.

Lints (nydus-xsw, 2026-11-10): the Kingdom shared Rust lint set (ambry `standards/RUST_LINTS.md`) is copied into the root `Cargo.toml` `[workspace.lints]` block and every member inherits it with `[lints] workspace = true`; `clippy.toml` allows unwrap/expect in tests. First rung denies `dbg_macro`, `todo`, `unimplemented`. Second rung (nydus-i33) denies `unsafe_code`: `naia-serde` scalars and arrays decode through `from_ne_bytes` and `Vec::try_into` instead of transmutes (the `Vec` path also drops already-decoded array items on a mid-array error, which the old `MaybeUninit` path leaked), and each remaining `unsafe` or `#[no_mangle]` item (miniquad JS bridge, zstd context Sync implementations, bevy `UnsafeWorldCell` access, the test allocator and wasm probe exports) carries a `// SAFETY:` comment and an item-scoped `#[expect(unsafe_code, reason = "...")]`, which rustc reports as red if it stops being needed. Add a rung by editing the workspace block only; never a blanket `allow`, never lint levels in gate argv.
